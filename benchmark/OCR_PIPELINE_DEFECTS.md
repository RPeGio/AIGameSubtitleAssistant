## D1 碎片化：单条字幕被拆成多段（嵌字链路，影响最大）

- **证据**：1:N 碎片化计数——glupov 10/22 条、moon 9/19 条、pierro 54/119 条；平均每条被拆 ~2~3 段。对齐文本相似度均值仅 0.43~0.49（产出段与参考条目只有部分重叠），是嵌字低分（17.6~21.5）的最大扣分项。
- **现象**：打字机式渐进文本随帧逐步显现，变化检测逐帧判定"变化"→ 每帧 OCR 只产出当前部分文本 → 相邻部分文本被切成独立段。
- **疑似根因**：`merge_frames` 的"前缀超集合并"依赖 run 连续性——一旦中间被空帧间隔打断（`empty_gap = max(interval×1.5, 0.8s)` 不够容纳打字机间隙）或相似基准失稳，渐进序列就断开成多段；相邻段合并（`merge_similar_adjacent`）对"文本互为前后缀/子串"的段未做拼接。
- **修复方向**：段级"包含关系拼接"（相邻且时间连续、文本互为前后缀的段合并取并集）；或把渐进检测从帧级提升到段级。
- **状态**：⬜ 待修复

## D2 段尾延伸：Δend 偏差显著大于 Δstart —— 原假设已证伪（改 D2′）

- **原始证据**：moon Δstart p95 1.24s vs Δend p95 5.62s；pierro Δstart 1.90s vs Δend 9.80s。阶段 1 帧级主边界精化（`eedcc3e`）已把段首压住，段尾未受益。
- **P0 诊断（2026-09-12）**：
  - moon（1:1 配对 n=10）：Δend 均值 0.764s、**中位 0.268s**，p95=max=5.616s 属小样本 p95=max 假象；唯一 >1s 的配对是**欠伸**（seg 28.334 vs ref 33.950，早 5.6s，sim 0.48）。
  - pierro（n=64，离线复算精确复现基线 64/54/1/0 及 p95）：**过伸 46 条（均值 +0.889s、中位 +0.899s、p95 +1.902s、最大 +2.414s）** vs **欠伸 18 条（均值 −5.902s、中位 −6.150s、最小 −20.967s）**；|Δend| 最大的 12 条**全部为欠伸**，形态一致（ref 8.2~29.8s / seg 仅 0.9~8.4s / sim≈0.48~0.49）。
- **结论**：**不存在多秒级"段尾过伸"**。Δend 的方差由 **D1 碎片化**（长显示被拆碎，某一片段与整条参考配对 → 欠伸）主导；过伸侧仅受 `end = 最后帧 + interval` 的 0.5s 量化支配，量级有界（≤2.41s）。
- **哈希锚定尾截断：不可用且有害**。moon 区域内容在显示期间持续漂移（Δanchor 由 0 涨至 34，无稳定平台，单哈希锚点不成立）；实测 T1（阈值游走）把 Δend 均值 0.764→**1.440s**、T2（静态冻结）→**1.776s**，**均更差**。
- **修复方向（D2′）**：撤销锚定尾截断；段尾改用"最后承载该文本的采样覆盖区间中点"（`end = 最后帧 + interval × 0.5`），预期过伸中位 +0.9s → ≈0、量化散布收至 ±0.25s（≤容差）。不需任何哈希/锚点。
- **状态**：✅ 已根因（原假设证伪）｜✅ **D2′ 已实施**（`end = 最后帧 + interval×0.5`；moon 验证：评分 21.5→**23.9**、Δend 中位 +0.103→**−0.099**（偏置归零）、Δend 容差内 50%→**64%**、过伸/欠伸 7/3→5/6 均衡；待 pierro 与语料基准回归确认）

## D4 字符级识别错误（三案例轻度合计 34 条，CER 均值 0.003~0.028）

- **证据**（glupov 最差匹配 Top10，全部为同模式系统性错误）：
  - `「缟玛瑙」` → `[编玛瑙】/「编玛瑙]`——**同形近字 缟→编 贯穿该案例全部条目**；全角「」→半角 [ ] 混杂、右括号丢失（`队员」` → `队员`、`临时连长」` → `连队J临时连长`）。
  - 省略号缩短（`……` → `…`）、漏尾字、换行断句差异（"…本质区别" → "…本质区别"被折行拆开）。
- **定位**：PaddleOCR 识别精度为主（形近字 + 字幕框边缘括号），非合并/逻辑缺陷；worker 白名单保留全半角括号使变体原样透传（宽松归一化后 CER 已抹平，对融合影响有限——LLM 融合按语义对应，括号/省略号差异预期可容忍，待融合基准验证）。
- **修复方向**：低优先。可选：白名单内做全半角括号归一、或对已知角色头衔做词典校正；更实际的是接受现状并在融合链路验证其影响。
- **状态**：⬜ 接受/低优先

## D5 边界量化残差（帧间隔网格 ±0.5s）

- **证据**：0.3s 容差下 ≤容差占比——glupov 0%、moon 60%、pierro 6%。阶段 1 精化已把段首压至 Δstart p95 1.2~1.9s，残差主要来自 0.5s 采样网格。
- **P0 补充（2026-09-12）**：**容差 0.3s 小于网格 0.5s** —— `end = 最后帧 + interval` 单独一项就系统性给出 +0.5s，故过伸侧中位 +0.899s（pierro）必然满额扣分。这解释了嵌字时间扣分为何普遍为 1.0，也说明段尾量化（D2′）的收益不小。
- **修复方向**：① D2′（段尾取半间隔）先削掉系统性 +0.5s；② 段首的"二分精化"既有待办与 D5 部分重叠（段首已帧级，段尾量化才是主残差）；③ 评测口径需承认"0.3s 容差 vs 0.5s 网格"的关系——若网格不下调，容差内的可达成率有理论上限。
- **状态**：⬜ 待处理（D2′ 先行；口径关系待与基准口径一并复核）

- **证据**（同源诊断，temp/probe/win_probe.py 入档）：glupov 语料 [卡佳和科利亚] 句帧级切 tq 67.900 → 71.033（寿命 3.1s），打字机 67.900→68.833 逐字补全，**完整态持续 2.2s** 且完整落在选区内（worker 同款逐帧 OCR 证实，68.833 起 conf 0.88 完整读出）——但管线只采到一次网格帧（68.200，部分态「…他们是壁炉之家的孩子」），其后 5 个网格样本与代表距离恒为 **3 = 阈值**（9×8 dHash 分辨率极限，1px 裁剪移位即可使距离 3→5~6 翻转，判别在噪声量级）；1a 帧级相邻差分直方图 {0:136,1:30,2:9,3:2,4:1,6:1}——补全过程每 33ms 仅动 0~2 位，**1a 无法在打字期间触发**；1b 保险丝锚点 67.898 + 4.0s = 72.198，晚于该句结束 → **两层补漏对此句全部失效**。分辨率对照（等比阈值）：17×16(256bit,thr12) 信号 16/噪声 5 可命中，但嵌字移动背景区实测变化帧 112→525（+4.7×）→ 全局提分辨率被否决。

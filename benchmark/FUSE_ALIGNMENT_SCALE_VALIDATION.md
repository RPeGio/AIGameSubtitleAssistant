# 融合对齐规模化验证（pierro 48min）：向量召回 + 单调 DP

- 日期：2026-10-05
- 定位：[FUSE_VECTOR_RECALL_VALIDATION.md](FUSE_VECTOR_RECALL_VALIDATION.md) 的**规模化验证**。该报告只验到 moon（5min/17 语料）与 glupov（11min/34 语料），把 pierro（48min/148 语料/含 51 条噪音行）列为"未测"；本报告补上这一例，并首次给出**逐段真值**与**准确率**（此前两案例只有"人工抽查合理"）。
- 同时是 [FUSE_PIPELINE_DEFECTS.md](FUSE_PIPELINE_DEFECTS.md) F13「替代路线」在最大规模素材上的第一次落地验证。
- 素材：`examples/benchmark_examples/pierro_questions.gsa`（本地留档，不入库）+ `quality_bench_test(voiced)_48min_reference.txt`（随 git 分发）
- 运行时：`runtime/deps_embed`（onnxruntime 1.20.1 CPU）+ `runtime/models/embed/multilingual-e5-small`（qint8，113MB）；**未引入 torch、不占 GPU**

## 一、结论速览

**向量召回 + 单调 DP 在 48min / 148 条语料规模上成立**，但**决定成败的不是对齐算法，而是输入卫生**：

| 臂 | 输入 | 正确 | 准确率 |
|---|---|---|---|
| A 基线 | 预校对后全量 120 段 | 106/120 | **88.3%** |
| **D 输入卫生** | 去掉 1 个"打字机前缀重复段" | **118/119** | **99.2%** |
| — 严格 DP 天花板（去重后） | — | 119/119 | 100% |
| C/D″ 非递减 DP（允许一对多） | — | 12/119 | 10.1% |

**删掉 1 个输入段，消除 12 处错误**（A 的 14 处错误里 13 处是一条漂移链，见 §五-3）。

对照 [FUSE_VECTOR_RECALL_VALIDATION.md](FUSE_VECTOR_RECALL_VALIDATION.md) 的 3B 路线：同素材上 3B 的错序判别器为随机水平（F13），本路线在 48min 规模上 99.2%。

## 三、真值如何建立（方法学）

pierro 语料**未附对应关系**，不能像预校对工程那样直接取用真值。本报告用**参考文本做中介**机械推导，再人工复核：

```
嵌入字段（英文，带时间轴）
    --IoU-->  参考文本块（中文，带时间窗；= 该时刻实际播出的台词）
    --文本匹配-->  语料行（中文；= 作品全集中的同一条）
```

- 参考文本 119 块 ⊂ 语料 148 条（与 F13 §277「语料是作品全集、转写侧只是切片出现部分」一致）；转写段与参考时间窗重叠合计 **96.5%**，时间轴可用作硬证据。
- 参考块→语料：**118/119 强匹配**；名字改名后 5 处转为"弱匹配"，**逐一核对均落在正确语料行**（分数下降只因参考仍用旧名，见 §六）。

### 3.1 判据选择：IoU（两次自纠的结论）

"嵌入段 → 参考块"的选块判据试过三种，前两种各有系统性误判：

| 判据 | 实测误判 | 成因 |
|---|---|---|
| 最大时间重叠 | 段106、段116 | OCR 段**跨参考块边界**时被判给更长的那一块 |
| 起始时刻落点 | 段2、5、11、17 | OCR 段起始**略早于**真实字幕起点时被判给上一块 |
| **IoU（交并比）** | 无 | 同时惩罚"跨到下一块"与"起点提前" |

6 处边界情形在 IoU 下全部判对，且不破坏原本正确的 4 处。

### 3.2 名牌段归位

参考文本只记录**台词**，不记录纯名牌，故名牌段没有自己的参考块，会被 IoU 归到相邻台词所属语料行（实测段13 `The Jester / …` 被归到语料[18]）。但语料中确实存在**纯名字条目**（[17] `[丑角】…`，用户补上遗漏的省略号后）——那才是名牌段的正确对应。归位判据：用该段**参考块的说话人**（中文）匹配"同样是纯名字"的语料条目。段13 真值 18 → **17**，且对齐结果随之判对。

## 四、实测结果

同输入、同模型、同 DP 参数（`skip_penalty=0.02`、`unmatched_penalty=0.25`，**均为未校准初值**），只变一个变量：

| 臂 | 变量 | 正确 | 准确率 |
|---|---|---|---|
| A 基线 | 现行表头规则 + 严格递增 DP | 106/120 | 88.3% |
| B | 修正表头规则 + 严格递增 DP | 106/120 | 88.3% |
| C | 修正表头规则 + **非递减** DP | 12/120 | 10.0% |
| **D** | **去掉 1 个前缀重复段** + 现行表头 + 严格 | **118/119** | **99.2%** |
| D′ | D + 修正表头 | 118/119 | 99.2% |
| D″ | D + 修正表头 + 非递减 | 12/119 | 10.1% |

**A 的 14 处错误分解**：

```
段 62–74   13 处  ← 单个前缀重复段引发的 +1 漂移链（93%）
段 38       1 处  ← 真实错误（相邻近似句歧义）
```

## 五、三个假设的检验（两个被推翻）

### 5.1 ❌ 表头规则：`NO.0217` 因含内部句点逃过剥离

`split_header` 的判据是「行短（≤16 字符）且**不含**句末标点」，而 `NO.0217` 含内部句点 `.` ⇒ 被误判为非表头，名字行留在正文参与编码。**缺陷确实存在**（语料表头剥离率 81.8% → 修正后 96.6%；22 条首行为 `NO.0217`），但**修正它对准确率无改善**（A 106 → B 106；D 118 → D′ 118）。

**结论**：缺陷真实，但**不是本案例的错误来源**。修正价值在于正确性与可解释性，不是分数。

### 5.2 ❌ 非递减 DP：严格递增无法表达"一对多"

真值确实存在一对多（同一字幕被 OCR 拆成多段），但把 DP 放宽为 `k >= j`（允许复用同一语料行）**大幅变差**（118 → 12）：它把"漂移"换成了**停顿**——DP 会停在高相似度的同一行上不再前进（实测段65–67 全挤到语料[86]、段117–120 全挤到[136]，平均错位 59.9 行）。

**结论**：**严格递增是更好的归纳偏置**。一对多的正确处置在**输入侧**（合并同属一条字幕的段），不是放宽 DP。

> 自纠：首版非递减实现把跳过代价写成 `skip_penalty * (k-1-j)`，`k==j` 时为 `-1`，变成"复用有奖励"的 bug。已改为 `max(0, k-1-j)` 后重测，**结论不变**（仍为灾难性更差），故上述判断成立。

### 5.3 ✅ 输入卫生：打字机前缀重复段（真实主因）

段61 是段62 的**严格前缀**（81 vs 186 字符）：OCR 在打字机逐字显示的中途抓到一帧，随后抓到完整句——**同一条字幕的两次抓取**，而非两条台词。

由于两者同属语料[80]，而严格递增 DP 不允许复用同一行 ⇒ 段61→80、段62→81，**此后整条链 +1 顺移 13 段**才重新同步。

**这是本报告最重要的工程发现：DP 会把一个局部输入缺陷放大成 13 段的全局错位。** 对齐前必须做输入卫生（合并/丢弃"互为前缀的相邻段"）。

## 六、角色名统一的影响（对 glupov 教训的限定）

**事实**：语料取自剧情录屏（中文源，角色名 `NO.0217`），与实况切片视频**不同源**（视频侧为 `MurderofBirds`——原始 OCR 实测产出 `MurderofBirds` 17 段、`NO.0217` **0 段**）。工程内已把两侧统一为 `MurderofBirds`。

**实测：名字统一对对齐结果毫无影响**（4 种组合全部 118/119）：

| 转写侧 | 现行表头 | 修正表头 |
|---|---|---|
| `NO.0217`（未剥离 18 段） | 118/119 | 118/119 |
| `MurderofBirds`（未剥离 1 段） | 118/119 | 118/119 |

**限定 [FUSE_VECTOR_RECALL_VALIDATION.md](FUSE_VECTOR_RECALL_VALIDATION.md) §二 的"表头必须先剥离"**：同形表头的危害**取决于它在哪一侧**——glupov 是**两侧**同形（互相淹没，3/22 → 22/22）；只在**查询侧**时，共享前缀对所有候选是近似常量偏移，不改变排序。

## 七、残留与局限

1. **仅 1 处残留错误**（段38）：`MurderofBirds / I've had a vague suspicion the Fatui and the Tsaritsa...` 真值语料[54]、预测[55]。两句是**同一说话人的相邻内心独白**（「尽管内心早就隐隐能够猜测到…」/「但听到「丑角」亲口说出这样的话…」），语义高度接近 ⇒ 向量歧义。这正是报告 §五-3 所述"同角色连续台词相似度天然接近"的场景，属 **T2 阈值校准**该覆盖的对象。
2. **单案例**：只验了 pierro 一例 48min。moon/glupov 规模小一个量级。
3. **阈值仍未校准**：`skip_penalty=0.02`、`unmatched_penalty=0.25` 与 margin 告警阈值（0.78/0.02）都是未校准初值，本报告**未调参**（保持与既有报告可比）。
4. **真值非独立标注**：由参考文本为中介推导 + 人工复核，不是逐段人工标注的对应关系；§三 已列出推导中的两次自纠与残留的 5 处弱匹配（均已核对）。
5. **语料噪音未单独度量**：pierro 语料含 51 条噪音行，本报告未按"是否噪音"分层统计。

## 八、给重构的结论

1. **召回路线在最大规模素材上成立**（99.2%，已达严格 DP 天花板）。
2. **对齐前必须做输入卫生**：合并/丢弃"互为前缀的相邻段"（打字机首帧）。收益 88.3% → 99.2%，**远大于任何算法侧调整**。
3. **保留严格递增 DP**，不要为"一对多"放宽；一对多在输入侧合并解决。
4. **表头规则缺陷应修但优先级低**：它是正确性问题（含内部句点的名字不被剥离），不是分数问题。
5. **阈值校准（T2）优先于算法调整**：段38 这类相邻近似句正是 margin 告警的目标场景。

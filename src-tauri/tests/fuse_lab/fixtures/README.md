# fixtures —— 融合/表头剥离的测试素材

## `pierro_names_with_internal_period.json`

**用途**：修复「表头（名字行）剥离对**含内部句点的名字**失效」这一缺陷时的测试素材。

**缺陷**：`fuse_lab.split_header` 的表头判据是「行短（≤16 字符）且**不含**句末标点」，
而 `NO.0217` 这类名字含内部句点 `.`，于是被误判为非表头 ⇒ 名字行留在正文里参与编码。
正确判据应看**结尾**是否为句末标点（`NO.0217` 结尾是 `7`，应剥离；
`原来是这么重磅的工程。` 结尾是 `。`，不应剥离）。

**素材内容**（取自 `pierro_questions.gsa`，2026-10-05 留档）：

| 侧 | 含 `NO.0217` | 说明 |
|---|---|---|
| 语料 corpus | 29 处（22 条首行 + 7 条句中） | 取自剧情录屏（中文源），角色名写作 `NO.0217` |
| 转写侧 embed_ocr | 17 段首行 | 实况视频嵌字 OCR 产物；后经人工改为 `NO.0217` |

**背景**：语料与实况切片视频**不同源**，故角色名不同（语料 `NO.0217` / 视频 `MurderofBirds`，
原始 OCR 实测产出 `MurderofBirds` 17 段、`NO.0217` 零段）。工程内现已把两侧统一为
`MurderofBirds`；本文件保留**统一前**的形态，因为 `MurderofBirds` 无句点、正常剥离，
无法复现该缺陷。

**实测影响**：同形表头只在**语料侧**才致命（glupov 带表头 3/22 → 剥离后 22/22）；
只在查询侧时对排序近似常量偏移，实测 4 种组合均为 118/119。故本素材的价值是
**回归测试**，不是性能提升。

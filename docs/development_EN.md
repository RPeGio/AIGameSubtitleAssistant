# Development Guide

English | [中文](development.md)

This document is for collaborators who want to understand the codebase or contribute. For the project vision and phased plan, see [GameSubtitleAssistant_Plan.md](../GameSubtitleAssistant_Plan.md); for usage, see the [README](../README.md).

## Tech stack

| Layer | Technology |
|---|---|
| Desktop shell | Tauri 2 (`protocol-asset`, dialog / opener plugins) |
| Frontend | Vue 3 + TypeScript + Pinia + Vue Router + Naive UI + Tailwind CSS 4 + Vite 6 |
| Backend | Rust 2021 (tauri / serde / image / uuid / ffmpeg-sidecar) |
| AI | PaddleOCR (Python worker), FunASR / MOSS (ASR), multilingual-e5-small + unified transition DP (fusion), llama.cpp + Qwen2.5-3B (LLM, test bench) |

Constraint: **fully offline**. The Rust side has no HTTP client and makes no network requests; every AI capability runs as a local subprocess.

| Module | Responsibility |
|---|---|
| `src-tauri/src/video/mod.rs` | ffprobe metadata (`get_video_metadata`); frame / audio extraction reused by OCR / ASR; FFmpeg located via system PATH → ffmpeg-sidecar dir, error `FFMPEG_NOT_FOUND` |
| `src-tauri/src/ocr/` (`mod.rs` facade + `commands`/`correct`/`merge`/`params`/`pipeline`/`refine` submodules) | Full OCR pipeline `run_ocr` (background thread + `ocr-progress` events): extract → change detection → window refinement → OCR → merge; `run_ocr_images` for direct screenshots; `approve_corpus_diff` to approve a corpus correction (single implementation of the replace rule, shared with the benchmark) |
| `src-tauri/src/ai_runtime/dhash.rs` | 64-bit dHash of cropped frames + Hamming-distance change decision |
| `src-tauri/src/ai_runtime/mod.rs` | AI runtime skeleton: provider traits + managers for OCR/ASR/LLM + `NoneProvider` placeholder (keeps the build compiling when the environment is absent; providers report "not ready") |
| `src-tauri/src/ai_runtime/paddle.rs` | PaddleOCR worker provider: resident subprocess, JSON lines over stdio (`{"id":1,"images":[...]}` / `ping` / `shutdown`) |
| `src-tauri/src/ai_runtime/funasr.rs` | FunASR provider: one-shot `funasr_worker.py <wav>` printing a JSON segment array on stdout; orphan workers cleaned before launch |
| `src-tauri/src/ai_runtime/moss.rs` | MOSS CLI provider: `moss-transcribe transcribe <model.gguf> <audio.wav> --format json`; leftover processes killed before transcribing |
| `src-tauri/src/ai_runtime/llm.rs` | llama.cpp provider: one-shot `llama-cli -m <model> -p <prompt> -st -n <tokens> --no-display-prompt` (used by the fusion-capability test bench; product fusion no longer needs it) |
| `src-tauri/src/ai_runtime/embed.rs` | Vector-fusion provider: one-shot `embed_worker.py <in.json> <out.json>` (E5-small encoding + unified transition DP); each output segment carries `ocr_index` / `score` / `product_text` / `candidates` / `masked` / `transition` / `reused` / `source_text`, plus stats |
| `src-tauri/src/ai_runtime/config.rs` | `RuntimeConfig`: runtime-directory and provider path/parameter resolution & validation (below) |
| `src-tauri/src/asr/mod.rs` | `run_asr`: audio extraction (RAII temp dir) → engine by params → `AsrSegment` list; re-entry guard + cancel (`asr_cancel`) |
| `src-tauri/src/llm/mod.rs` | `run_llm`: single-prompt inference (frontend test bench); `llm-progress` events |
| `src-tauri/src/fuse/mod.rs` | `run_fuse`: vector recall + unified transition DP fusion, producing the final subtitle segments and their audit metadata (see [Fusion pipeline](#fusion-pipeline-fusemodrs)) |
| `src-tauri/src/project/mod.rs` | Project / Track / TimelineEvent model, `<project-name>.gsa` I/O (magic header `GSA-PROJECT v1` + JSON body, atomic write), recent projects |
| `src-tauri/src/export/mod.rs` | `export_track_subtitle`: single-track SRT / ASS / LRC / TXT (SRT/LRC/TXT written with a UTF-8 BOM so players don't misread them as GBK; ASS has a fixed style with `\` / `{}` escaped) |

`subtitle/` and `timeline/` are empty shell modules: subtitle writing lives in `export`, the timeline in the frontend store.

## AI runtime layer

### The runtime/ directory

```
runtime/
├── config.json          # the single config file (merged writes by bootstrap scripts)
├── python/              # embedded CPython 3.12.10 (NuGet package)
├── deps/                # OCR pip deps (--target isolated)
├── deps_gpu/            # OCR GPU-only pieces (optional, bootstrap_ocr_gpu.ps1; runtime PYTHONPATH=deps_gpu;deps)
├── deps_funasr/         # FunASR pip deps (torch isolated from paddle)
├── deps_embed/          # vector-recall pip deps (onnxruntime CPU + tokenizers, fusion)
├── models/
│   ├── paddleocr/       # PP-OCRv5 cache
│   ├── funasr/          # Fun-ASR-Nano + VAD + speaker models (modelscope cache)
│   ├── embed/           # multilingual-e5-small (ONNX qint8, fusion)
│   ├── moss/            # moss-transcribe-<quant>.gguf
│   └── qwen/            # qwen2.5-3b-instruct-q4_k_m.gguf (optional, test bench)
├── worker/              # worker scripts copied by bootstrap
└── bin/                 # moss-transcribe.exe, bin/llm/ (llama.cpp)
```

### Key config.json fields

| Field | Meaning |
|---|---|
| `python_path` / `worker_script` / `deps_dir` / `model_dir` | OCR worker paths (relative to the runtime dir) |
| `ocr_model` | `mobile` (default) or `server` (PP-OCRv5 tier) |
| `language` / `dev_debug` | OCR language; debug frame dump (`temp/`) |
| `moss_binary` / `moss_model` / `moss_threads` / `moss_device` | MOSS; `moss_device`: empty=auto / cpu / cuda / vulkan |
| `llm_binary` / `llm_model` / `llm_threads` | llama.cpp (optional, fusion-capability test bench only) |
| `asr_provider` | `moss` / `funasr` / empty=auto |
| `funasr_worker` / `funasr_deps` / `funasr_model_dir` / `funasr_device` / `funasr_language` / `funasr_timeout_minutes` | FunASR |
| `embed_worker` / `embed_model` / `embed_tokenizer` / `embed_deps_dir` | Fusion worker script / E5-small model / tokenizer / deps paths; written by `bootstrap_embed.ps1`, shared by product fusion and the lab; **all four must be set together, or all left empty** |

### Runtime directory resolution order

1. `GSA_RUNTIME_DIR` env var (must contain `config.json`)
2. Walk upward from the exe directory looking for `runtime/config.json` (in dev, the repo root)
3. Fallback: Tauri `app_data_dir/runtime`

`validate()` ensures relative paths stay inside the runtime dir (path-traversal guard) and that the python / moss / llm binaries exist; the `embed_*` group must be **all four set or all empty** (a partial group is a config error, so it fails at validation instead of at runtime) and, when set, each of the four paths gets the same traversal check; model files are not checked (providers report "not ready").

## Data model (`project/mod.rs`)

```
Project
├── path                     # absolute path of the .gsa project file (identity = file; multiple projects may share a folder)
├── video                    # clip video — the global timeline reference
├── source_video             # story recording — text source for corpus OCR
├── corpus: Vec<CorpusItem>  # reliable text corpus (independent of tracks; consumed by fusion)
├── corpus_ocr_diffs: Vec<Diff>  # pending text corrections from corpus OCR (glossary; empty by default, legacy-compatible)
└── tracks: Vec<Track>
     ├── track_type: "ocr_region" | "ocr_text" | "asr" | "manual" | "translation"
     ├── track_role:  "streamer" | "game"        # asr tracks only, defaults to game
     ├── scope:       "control" | "output"       # control tracks (e.g. OCR regions) / output tracks, defaults to output
     ├── page:        "corpus" | "asr" | "fuse" | "editor"   # control tracks only
     ├── video:       "source" | "clip"          # which video source the track belongs to, defaults to clip
     ├── preview_visible / events
```

`TimelineEvent` is a serde tagged union (`type` field) with six variants:

| Variant | Meaning |
|---|---|
| `ocr_text` | Reliable story text (corpus source, with confidence) |
| `embed_ocr` | Hardsub text recognized from the clip (the "text to be replaced" — same shape as ocr_text, opposite semantics) |
| `ocr_region` | Normalized subtitle region (control track) |
| `asr` | Transcript segment (+ speaker; **`character` is no longer written by fusion** — plain-text contract; it can only be set by hand or synced from the track name) |
| `fused` | Fusion output (the final-subtitle track) |
| `manual` | Manual event |

`src/types/index.ts` mirrors the Rust structures in TypeScript; new fields must be added on both sides.

The project is stored as a single `<project-name>.gsa` file in the project folder: the first line is the magic header `GSA-PROJECT v1`, followed by the JSON body (the structure above — fields unchanged). The file name derives from `sanitize(project-name)` (Windows-illegal characters replaced); writes are atomic (temp file + rename). **Project identity = the .gsa file path**: multiple projects may coexist in one folder; opening accepts either a `.gsa` file path directly or a folder path (which must contain exactly one `*.gsa` — keeps older recent-project entries working); saving always writes back the file `path` points to, and renaming a project only changes the JSON field, not the file name.

## Frontend structure

- **Router** (`src/router/index.ts`): `/` welcome; `/project/:path` → `ProjectLayout` with children `corpus` / `asr` / `fuse` / `editor` (redirects to editor by default).
- **ProjectLayout**, three columns: `AppSidebar` (four-step navigation + save status) + workspace `<router-view>` + `ReviewPane` (the global proofing area: VideoPlayer + Timeline + TrackOverview). Owns the global shortcuts Ctrl+S / Ctrl+Z / Ctrl+Shift+Z.
- **stores/project.ts**: project state + all Tauri call orchestration. Deep-watches the whole project object and autosaves with a 1-second debounce (`applyingSaved` guards against save loops; async switching guards against races); best-effort flush on close.
- **stores/timeline.ts**: the timeline store. Components obtain their instance via `inject(TIMELINE_STORE_KEY)`, falling back to the global store only when absent — so the same component tree can host several independent timelines (the corpus mini-timeline, the hardsub timeline, the main review timeline).
- **stores/fuseAudit.ts**: the pure logic of the fusion audit table (no Vue dependency) — risk tiering (`auditRisk`: reviewed > structural tier A (masked / reset / reused / unmatched) > low-score tier B (`score < 0.82`)), row building and sorting, counts, the four verdicts (`applyFusedDecision`: keep / replace from candidates / pick from the full corpus / mark unmatched) and `reused` recomputation; `project.ts` exposes it as `fusedAuditRows` / `applyFusedAuditDecision`, wiring it into project state and the undo/redo stack (a failed decision has zero side effects).
- **Views**: `Welcome` (project creation / recent projects), `CorpusView` (three corpus sources), `AsrView` (② timing + transcribe: ASR (voiced) / hardsub OCR (unvoiced) + speaker tagging), `FuseView` (dual readiness cards → fusion → audit table: tier A expanded by default, low-score tier B folded and tagged, full-corpus picker loaded lazily), `Editor` (per-event proofreading of the fused track + export).

## Key pipelines

### OCR pipeline (`ocr/mod.rs`)

```
extract frames (ffmpeg) ─► crop region ─► dHash change detection (skip if Hamming ≤ threshold)
                        ─► PaddleOCR worker (changed frames only) ─► carry text forward ─► merge into segments
```

- Parameters (frontend defaults): frame interval 0.5s, dHash threshold 3, batch size 16, merge similarity 0.3, minimum subtitle length 1.5s (`DEFAULT_MIN_SUBTITLE_SEC`).
- **Merge rules** (`merge_frames`): adjacent similar texts join the same run; the run's final text is chosen by **majority vote** (instead of "longest wins" — a longer text polluted by noise scores low on total similarity and loses); empty frames tolerate a `(interval*1.5).max(0.8)` flicker window; typewriter-style progressive text (prefix supersets) merges into one event keeping the longest text.
- Output destination is decided by the frontend: source mode → corpus (timing stripped); clip + page=asr → the embed_ocr (hardsub) track.
- **Corrections only mark, never rewrite** (user decision, 2026-09-24/25): the last step runs punctuation
  normalization (silent, targets configurable) and fuzzy glossary matching, but only **emits**
  `Diff { old: Vec<String>, new: String }` (`old` is a set: one term may match several misread forms;
  diffs are aggregated by `new`). `run_ocr` returns `(Vec<OcrSegment>, Vec<Diff>)`, leaving text
  "normalized but unrefined"; the user approves each entry in the Corpus page. Approve = replace across
  all corpus items and drop now-duplicate items; Discard = remove the entry only. Both are undoable.
  The glossary is **corpus-OCR only** (no entry point in the hardsub panel). The approve rule exists in
  two places and must stay in sync: `tests/common::apply_diffs_to_segments` ↔
  `stores/project.ts::approveCorpusOcrDiff`.

### Fusion pipeline (`fuse/mod.rs`)

- **Route**: local multilingual vector recall (multilingual-e5-small qint8, ONNX / CPU) + a **unified transition DP**. The corpus and the transcript segments are encoded separately into a similarity matrix, then a global monotonic DP picks the best overall path — transitions are advance / reuse (`repeat_penalty`) / reset (`reset_penalty`, allowing a jump back after corpus lines were skipped) / unmatch (`unmatched`). Four benchmark cases measure **210/236 scored segments**, rising to **226/236 (95.8%)** with the "should-not-match" mask enabled; thresholds and criteria are calibrated in [benchmark/FUSE_THRESHOLD_CALIBRATION.md](../benchmark/FUSE_THRESHOLD_CALIBRATION.md) §7.9. The earlier llama.cpp LLM index-mapping route measurably **did not perform cross-language semantic alignment** (defect ledger F13) and was retired with this route; `src/llm/` and `run_llm` survive only for the fusion-capability test bench.
- **Plain-text contract**: matched segments copy the corpus text verbatim (line breaks and name lines included), unmatched segments keep the transcript text; nothing is rewritten, no prefix is stripped, no line-break normalization is done. It **produces no speaker / character name** — `character` is no longer written by fusion (defect ledger F1/F2).
- Input contract (enforced by the frontend): texts come **only from the corpus** (no fallback to ocr_text tracks — that would treat "text to be replaced" as reliable); the transcript side = game-role ASR segments + embed_ocr hardsub events (**the two transcript-side options may coexist and are consumed here uniformly**; hardsub events overlapping ASR beyond a ratio are dropped — voice-covered lines don't need hardsub). Since R2 no speaker first line is injected into the transcript text any more (that injection disturbed prefix attention and was removed).
- "Should-not-match" mask (optional, per-material switch, a frontend checkbox, off by default): the criterion is "the content of this transcript segment cannot fit into any corpus line" — `len_sub >= 1` and `len_sub <= α · max{len_corpus[j] : j ∈ top-K}` (α=0.95 / K=3 / similarity tie tolerance `tie_eps`=0.0015). False positives are zero across the four cases, but the benefit depends on the language pair (the display language says less per unit than the corpus language), so it is switched on per material (currently only vesna). **Changing the embedding model or the material requires recalibration** (the effective `tie_eps` window is only about 2× wide).
- Output: timing follows the transcript side; each segment carries audit metadata `ocr_index` / `score` / `product_text` / `candidates` / `masked` / `transition` / `reused` / `source_text` (the transcript text as of fusion time) / `reviewed` (manually proofread), feeding the frontend audit table's tiering and four verdicts. Degradation counters: `masked_segments` (segments the mask judged "should not match"), `reused_segments` (segments reusing a corpus line); an out-of-range `ocr_index` is a hard error, never a silent downgrade.
- Tooling: `scripts/fuse_core.py` (single Python source of truth: encoding / similarity / DP / mask), `scripts/embed_worker.py` (the product's one-shot worker), `scripts/fuse_worker_parity.py` (lab ↔ worker parity check); lab and criteria in `src-tauri/tests/fuse_lab/` and `scripts/fuse_*.py`.

## Testing

Eight integration tests under `src-tauri/tests/`: end-to-end `ocr_e2e.rs`, `asr_e2e.rs`, `fuse_e2e.rs`, `llm_e2e.rs`, `ocr_bench_refinement.rs`; quality benchmarks `bench_corpus.rs`, `bench_hardsub.rs`, `bench_pierro_embed_ocr.rs` (all `#[ignore]`; materials and how to run them: [benchmark/README.md](../benchmark/README.md)). Most are end-to-end and **require a provisioned runtime** (models and binaries in place) to pass; each module also has environment-free unit tests (e.g. "not ready → error, no callback fired").

**Fusion capability benchmark** (the former `bench_fusion.rs`, `#[ignore]`) was deleted together with the LLM fusion route: it used hand-written clean cases to tell whether "cross-language semantic alignment" actually happens — the corpus order was turned into a derangement so that the "copy the index" identity mapping is wrong on every entry, letting content accuracy be compared directly against the random baseline. The measured conclusion is on record in [benchmark/FUSE_PIPELINE_DEFECTS.md](../benchmark/FUSE_PIPELINE_DEFECTS.md) F13; the Python version of the same discriminator still lives in `fuse_lab` (next section) and can reproduce it.

```powershell
cd src-tauri; cargo test
```

**Fusion-alignment lab** (`src-tauri/tests/fuse_lab/`, Python, not part of `cargo test`) is the reproducible tooling behind those conclusions and, after T4 landed, still the **calibration and regression source** for fusion thresholds and criteria: LLM discriminator, **vector-recall discriminator**, and an **offline validation pipeline** (pre-proofread project → recall + monotonic DP → SRT).
On the product side, `scripts/fuse_worker_parity.py` additionally runs a segment-by-segment parity check between the lab and the product worker (8 groups, zero differences).
It depends on the CPU runtime installed by `scripts/bootstrap_embed.ps1` (onnxruntime + E5-small qint8, 113MB, no GPU).
See [src-tauri/tests/fuse_lab/README.md](../src-tauri/tests/fuse_lab/README.md); the route conclusion is in [benchmark/FUSE_VECTOR_RECALL_VALIDATION.md](../benchmark/FUSE_VECTOR_RECALL_VALIDATION.md).

## Packaging & distribution status

- `tauri.conf.json` does **not** yet configure `bundle.resources`: installers will not carry `runtime/`. The distribution plan (bundle `runtime/**` and teach `config.rs` the installed resource layout) is noted as a TODO in `config.rs`.
- FFmpeg is not bundled: the app searches PATH → the ffmpeg-sidecar directory.
- Model downloads exist only in the bootstrap scripts; the app side only performs readiness checks (the `check_*` commands).
